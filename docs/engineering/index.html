01

Ideia

Tudo começa com um problema, não com uma solução. A ideia é capturada em linguagem natural, focando no porquê e em quem é impactado.

01CAPTURA DO PROBLEMA

Uma anotação curta descrevendo a dor, a oportunidade e o resultado esperado — sem comprometer com implementação. É o insumo para o brainstorming que vem a seguir.

Artefato
docs/ideas/<slug>/idea/input.md
Foco
Problema e impacto, não solução
02

Discovery

Brainstorming colaborativo transforma a ideia em um PRD — em nível de produto e negócio, sem detalhe técnico.

02PRDsuperpowers:brainstorming

Exploração de intenção e requisitos uma pergunta por vez, alternativas com trade-offs e uma recomendação. O resultado é um PRD publicado com a identidade da marca (tema escuro, accent lime), revisável.

Artefato
discovery/prd.html (versionado)
Nível
Produto / negócio — pt-BR
Portão
PRD revisado e aprovado
03

Solution Design

O PRD aprovado vira desenho técnico: como resolver, com quais decisões de arquitetura, e como fatiar o trabalho em incrementos entregáveis.

03DESENHO DA SOLUÇÃO

Decisões de arquitetura, integrações e riscos, com a solução fatiada em incrementos independentes. Cada incremento entra no loop do superpowers — brainstorming → spec → plano → build — no seu próprio ciclo.

Artefato
solution/solution-design.html
Decompõe em
Incrementos → loop do superpowers
Portão
Solution design aprovado
04

Spec

Antes de tocar em código, cada incremento ganha um documento de design técnico — com objetivo, não-objetivos, decisões e fases de entrega.

04DOCUMENTO DE DESIGNbrainstorming

Um brainstorming técnico fecha o escopo (incluindo o que fica de fora), registra a decisão arquitetural principal e organiza o trabalho em fases independentes, cada uma testável e commitável. Passa por uma auto-revisão e pela revisão do autor.

Artefato
docs/superpowers/specs/AAAA-MM-DD-<tema>-design.md
Contém
Contexto · escopo/não-escopo · decisões · fases · riscos
Portão
Spec revisado e aprovado
05

Plano

O spec aprovado é traduzido em um plano de implementação detalhado.

05PLANO DE IMPLEMENTAÇÃOsuperpowers:writing-plans

Cada fase é independente, testável e commitável, com critérios de aceite claros e a ordem que minimiza retrabalho — lint primeiro (base), depois refatorações guardadas por testes, depois portões.

Saída
Fases ordenadas com critérios de aceite
Princípio
1 fase → 1 (ou poucos) commits
06

Implementação

Cada fase é construída sob TDD estrito: nenhum código de produção sem um teste falhando antes.

06RED · GREEN · REFACTORtest-driven-development

Escreva o teste e veja-o falhar (RED). Escreva o mínimo para passar (GREEN). Limpe mantendo o verde (REFACTOR). Refatorações puras são guardadas pelos testes existentes. Commits seguem Conventional Commits, um por fase.

Feedback imediato
Hook lint-after-edit linta cada arquivo editado
Revisão
Subagentes acoplados via hooks/checkpoints do superpowers (ver Gates)
Commits
feat · fix · refactor · test · docs · chore
07

Quality Gates

Duas camadas de portões, todas locais: checks determinísticos e revisores em forma de subagentes — acoplados ao loop do superpowers via hooks. O pre-push é a fonte de verdade sobre o que pode entrar.

Checks determinísticos

a cada edição

EDIT

  • Hook lint-after-edit
  • ESLint no arquivo tocado
  • Advisório (não bloqueia)
pre-commit

COMMIT

  • Prettier (re-stage)
  • ESLint + typecheck
  • commitlint (Conventional)
pre-push · autoritativo

VERIFY

  • build @forja/domain
  • typecheck — todos os pacotes
  • lint — todos os pacotes
  • testes unitários — todos
# o gate que decide o que vai para produção
$ pnpm verify
  → build domain  → typecheck  → lint  → test   # falhou? o push é barrado

Testes de integração (*.integration.test.ts) precisam de Postgres e rodam sob demanda via pnpm --filter @forja/web test:db — fora do gate para não flakar. Cobertura é medida (pnpm coverage) com um piso que sobe conforme os testes crescem.

Revisores como subagentes · acoplados via hooks

O loop do superpowers pluga subagentes revisores via hooks (PostToolUse) e nos checkpoints da execução. São eles que produzem os gates de qualidade e segurança — e bloqueiam em achados de alta severidade.

↺

lint-after-edit

hook · PostToolUse — roda o ESLint no arquivo recém-editado. Feedback imediato e advisório, não bloqueia.

◐

ux-patterns-reviewer

subagente — valida a UI contra o design system (modo plano + diff). Bloqueia em achados altos.

⌥

code review

subagente — revisa o diff contra o plano e os padrões do projeto, com severidade e confiança.

⛨

security review

subagente — varre as mudanças pendentes em busca de vulnerabilidades antes do push.

08

Produção

Verde no pre-push e confirmação explícita: o código sobe para a main e é entregue.

08DEPLOYfinishing-a-development-branch

Nunca se faz push em main sem confirmação — ele dispara a entrega. O web sobe como imagem Docker via compose; o app mobile usa EAS Workflows (preview no push em main, produção em tags v*).

Web
Imagem Docker · deploy/forja/compose.yml
Mobile
EAS Workflows — preview / produção
Portão
pre-push verde + confirmação de push
★

Princípios

As regras transversais que valem em todas as etapas.

⌗

Monorepo em camadas

pnpm: mobile · web · domain. Fluxo route → service → repository → db, imposto por ESLint.

RG

TDD estrito

Nenhum código de produção sem um teste falhando antes. Viu falhar, então implementa.

!

Erros tipados

AppError + toErrorResponse mapeiam código e status HTTP. Nada de catch-all que vira 401.

⎇

Commits convencionais

feat/fix/refactor… Nunca push em main sem confirmação explícita.

文

Idiomas

Código e comentários em inglês; texto de interface em pt-BR.

◐

Design system de marca

Bebas Neue + Syne + accent lime, via tokens. Pesquisa de UX antes de telas novas; ux-patterns-reviewer guarda o padrão.

✓

Gate local é a verdade

Sem CI. O pre-push (pnpm verify) decide o que entra — local e determinístico.

▤

Documentação viva

PRD → solution → spec versionados e publicados no GitHub Pages. O processo é tão rastreável quanto o código.

⚇

Revisores como subagentes

Acoplados ao loop do superpowers via hooks/checkpoints; formam os gates de segurança e qualidade, bloqueando em alta severidade.
